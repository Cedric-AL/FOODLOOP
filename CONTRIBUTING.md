# Contributing to FoodLoop

Thank you for contributing to FoodLoop. This project is still in its early development stage, so clear organization and communication are important.

## Branching

Use descriptive branch names based on the work being done:

- `feature/frontend-dashboard`
- `feature/backend-donations`
- `feature/database-schema`
- `fix/backend-health-check`
- `docs/setup-guide`

## Commit Messages

Write clear, professional commit messages that explain what changed and why.

Examples:

- `feat: initialize backend spring boot project`
- `feat: add frontend vite react structure`
- `docs: add setup instructions for team environment`
- `fix: configure health endpoint for backend`

## GitHub Issues

- Create issues for new features or fixes.
- Keep issue titles specific and clear.
- Link related pull requests when applicable.

## Pull Requests

- Create a pull request for each logical set of changes.
- Include a short summary of what the PR changes.
- Mention any manual setup steps or environment requirements.
- Keep frontend and backend work in separate PRs when possible.

## Code Review

- Review changes carefully before merging.
- Check for correctness, clarity, and project consistency.
- Confirm that no secrets or real credentials are committed.

## Testing Before Pushing

Before pushing your work:

- Run relevant backend tests.
- Run frontend build checks when applicable.
- Verify the project still starts in its intended environment.

## Main Branch Protection

Do not push directly to `main` unless explicitly instructed. Create a branch and open a pull request instead.

## Organization

Keep frontend and backend changes organized and documented so that team members can understand the purpose of each update.
